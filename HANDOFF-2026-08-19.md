## Three things that are the difference between resuming and re-deriving

### 1. The stated-k constraint is UNTESTED, not failed

The idea: a synthesis declares its own k in its abstract, and the included-studies table's
row count should equal it. A therapies table almost never will — so the constraint comes
from a part of the document written for a different purpose, which is why it can't be
satisfied by accident. Same reason a known-answer instance works.

**It never ran.** The module was generated by string-substitution inside a shell heredoc,
which stripped `\b` from every regex; Python printed `SyntaxWarning: invalid escape
sequence` and the results were read anyway. `stated_k` reported *"no abstract in the
record"* on an article containing two `<abstract>` elements — the function did not execute
as written.

**Every NOT-ASSESSABLE in that run is void, not conservative.** The idea is unopened, not a
dead end. It was discarded with the working tree; re-implement it, **by writing the file
directly**.

### 2. PMC13250634 is the best available test case, and it was never reached

*Pharmacological Interventions for Hereditary Transthyretin-Related Amyloidosis With
Polyneuropathy.* It carries:

| Table | Rows |
|---|---:|
| **`Characteristics of the included studies.`** | **6** |
| `Network meta-analysis results and GRADE assessments for …` | 18 |
| `Network meta-analysis results and GRADE assessments for …` | 13 |
| `Network meta-analysis results and GRADE assessments for …` | 17 |

A genuinely discriminating instance: one correctly-captioned included-studies table beside
three same-shaped result tables that must be rejected. **The earlier caption heuristic never
reached it** — the two-hop run opened only the first three PMC IDs and this was outside
them. Start the next table-selection attempt here.

It is also the correct-negative case for the known-answer test: a *polyneuropathy* review
that legitimately does not contain the ATTR-**CM** trials, so it proves the check
discriminates rather than merely passes.

### 3. Write the file directly — the mangling path is the finding

Generating regex-dense code by string substitution inside a heredoc is a corruption path.
Use the file-write tool. And an interpreter warning is an instrument declaring itself
broken: it is a stop, not noise.
